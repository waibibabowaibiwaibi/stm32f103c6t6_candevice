# 五分钟快速开始

> [!WARNING]
> 本页描述的是主分支的外置 USB-UART 版本。当前 native USB 初稿分支请改看[板载 USB 初稿说明](NATIVE_USB_PROTOTYPE.md)，CAN 引脚也已从 PA11/PA12 改为 PB8/PB9。

这份说明以“第一次拿到源码和一块 STM32F103C6T6 板”为起点。先不要连接未知车辆或生产设备；请在实验台上使用可控电源和第二个 CAN 节点完成验证。

## 1. 准备硬件

- 带 8 MHz 外部晶振的 STM32F103C6T6 最小系统
- 经典高速 CAN 收发器或模块（作者实测为 SN65HVD230，但不限定该型号）
- 3.3 V USB-UART 转换器
- ST-Link 或 CMSIS-DAP SWD 下载器
- 第二个可配置到相同波特率、能够 ACK 的 CAN 节点
- 两个 120 Ω 终端电阻、杜邦线或合适的线束

CAN 收发器的供电、待机/使能引脚和逻辑阈值因型号而异，以它的数据手册为准。SN65HVD230 只是实测示例；换用其他符合 ISO 11898-2 的经典高速 CAN 收发器时，还要确认逻辑电平、最高速率和模块是否自带终端电阻。PA11/PA12 绝不能直接接 CANH/CANL。

## 2. 接线

先断电接线。

### USB-UART

| USB-UART | STM32F103 |
|---|---|
| TXD | PA10 / USART1_RX |
| RXD | PA9 / USART1_TX |
| GND | GND |

USB-UART 只负责串口通信。本项目的 STM32F103 固件不是 USB CDC 设备，电脑上出现的 COM 口或 Linux 串口设备来自 USB-UART 转换器。

### CAN 收发器

| STM32F103 | CAN 收发器 |
|---|---|
| PA12 / CAN_TX | TXD |
| PA11 / CAN_RX | RXD |
| GND | GND |

将收发器的 CANH、CANL 和总线地接入测试总线。总线两端各放置一个 120 Ω 终端电阻；断电后在 CANH 与 CANL 之间通常可测到约 60 Ω。不要在每个节点都增加终端电阻。

### SWD 下载器

连接 `SWDIO`、`SWCLK`、`GND`，并按下载器要求提供或检测目标电压。固件保留 SWD，不需要占用 JTAG 全部引脚。

## 3. 烧录固件

从 GitHub Release 下载 `c6t6-<version>.hex`，使用下载器直接烧录。

如果使用 `.bin`，起始地址必须设置为：

```text
0x08000000
```

也可以先按主 README 的说明构建源码，再烧录构建目录中的 `c6t6.hex`。复位后 PC13 LED 默认熄灭；固件接受发送命令或收到 CAN 帧时会产生约 35 ms 的活动脉冲。连续高流量时它可能看起来常亮；若在没有流量时仍持续点亮，则可能进入了致命错误处理。

## 4. 打开上位机

1. Windows 从 Release 下载并运行 `UART-CAN-Host-<version>-windows-x64.exe`；Linux 下载 `UART-CAN-Host-<version>-linux-x64.tar.gz`，校验同名 `.sha256` 后解压运行 `./UART-CAN-Host`，也可按[上位机说明](../host_app/README.md#构建与运行-linux-版本)从源码构建。
2. Windows 首次运行未签名 EXE 时可能显示 SmartScreen 提示；先用 `SHA256SUMS.txt` 校验文件来自本仓库 Release。
3. 点击“刷新串口”，选择 USB-UART 对应的 COM 口或 `/dev/ttyUSB*`、`/dev/ttyACM*` 设备。
4. 保持 `921600` 波特率，点击“连接”。
5. 保持“每秒读取设备状态”勾选。
6. 上位机会读取设备 CAN 波特率；默认应显示 `500 kbit/s（已生效）`。如需其他速率，选择后点击“应用 CAN 波特率”，并把第二个 CAN 节点设为相同值。

Linux 如出现串口权限错误，按[权限说明](../host_app/README.md#linux-串口权限)加入设备所属组并重新登录。界面默认跟随系统亮暗，右侧“主题”可手动选择亮色或暗色。

如果状态数字能够刷新，PC ↔ USB-UART ↔ MCU 链路正常。若没有响应，请先检查 TX/RX 是否交叉、GND 是否共地，以及固件是否运行。

## 5. 发送第一帧

确保另一 CAN 节点已经上电、波特率与上位机显示的设备 CAN 波特率一致，并能够 ACK 报文。

在上位机中填写：

- 帧类型：数据帧
- 帧格式：标准帧
- 每次帧数：`1`
- 发送次数：`1`
- CAN ID：`123`
- DLC：`8`
- 数据：`11 22 33 44 55 66 77 88`

点击“发送”。上位机出现一条黄色 `TX` 记录，表示命令已加入本机串口发送队列。请在第二个 CAN 节点确认收到 ID `0x123` 的报文；`TX` 本身不等于单片机确认或总线 ACK。

## 6. 接收第一帧

让第二个节点发送：

```text
ID: 0x321
DATA: DE AD BE EF
```

上位机应显示一条蓝色 `RX` 记录，同时“CAN 接收”计数增加。至此，UART → CAN 和 CAN → UART 两个方向都已验证。

## 验收清单

- [ ] 上位机可以连接正确的串口设备
- [ ] 状态计数器每秒刷新
- [ ] 上位机读出的 CAN 波特率与第二个节点一致
- [ ] 第二个节点收到 `0x123` 测试帧
- [ ] 上位机收到第二个节点的 `0x321` 测试帧
- [ ] `UART 丢弃`、`命令丢弃`、`发送丢弃` 和 `UART 错误` 保持为 0
- [ ] 断开或短暂制造总线故障后，恢复连接时 `CAN 恢复` 计数符合预期

任何一步失败，请转到 [故障排查](TROUBLESHOOTING.md)。
